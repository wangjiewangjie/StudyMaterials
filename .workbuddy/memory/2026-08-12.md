# 2026-08-12

## 播放详情页加载性能优化

**问题**: VideoPlayer 的 loadSource() 在创建播放器前 await /api/refresh/:id，导致用户每次打开详情页都要等待 5-20 秒（抓取上游 HTML + cheerio 解析 + 串行 resolve player URL + 同步写 index.json）。

**修改文件**:
- `server.js`: 1) 新增 indexIdMap (O(1) findById) 2) 新增 writeIndexAsync (异步写盘不阻塞响应) 3) 新增 refreshCache (2 分钟 TTL 避免重复抓取) 4) /api/refresh/:id 用 Promise.all 并行解析多视频 URL
- `frontend/src/VideoPlayer.jsx`: loadSource 改为立即用缓存的 m3u8 地址启动播放器，/api/refresh 后台异步执行；刷新完成后若播放器仍在 loading 且地址已变则热切换；HLS 销毁时额外调用 hls.destroy()

**效果**: 缓存地址有效时 1-2 秒开播（原 5-20 秒）；地址过期时 2-5 秒（刷新完成后热切换）

## 视频加载卡在 loading 的修复

**问题**: 优化后出现新问题：视频可能一直卡在 loading 状态不报错。原因：1) HLS 超时设置 60s/90s 太长，用户等很久才看到错误 2) 后台刷新完成后 URL 没变但播放器已死（HLS 报错回退到 loading），没有重启播放器 3) 缺少整体加载超时机制

**修改**: `frontend/src/VideoPlayer.jsx`
- 新增加载看门狗（loadingTimerRef）：12s 显示"加载较慢"提示 + 刷新按钮（不打断播放器）；25s 强制超时报错（若刷新仍在进行则再延 15s）
- 新增 playerAliveRef 追踪播放器是否存活（HLS 致命错误后标记为 false）
- 修复"刷新完成 URL 没变但播放器已死"的 bug：刷新完成后检查 playerAliveRef，若已死则重启播放器
- 刷新 fetch 超时从 60s 降到 30s
- loading 状态 12s 后显示"刷新重试"按钮，error 状态保留"重新加载"按钮
- cleanup useEffect 清理看门狗定时器

## 修复播放器在 ready/loading 之间闪烁

**问题**: 播放器在"可播放"和"正在加载视频流"两个状态间快速切换，页面闪烁。

**根因**: 后台刷新完成 → 调用 onTags 回调 → DetailView 的 handleTags 调用 setLocalVideos(next)（即使 URL 相同，也是新数组引用）→ DetailView 重新渲染 → primaryVideo = localVideos[0] 是新对象引用 → VideoPlayer 的 activeVideo 变了引用 → loadSource 的 useCallback 依赖 activeVideo（对象）变了 → loadSource 重建 → useEffect 触发 → 播放器销毁重建 → phase: ready→loading→ready 循环 = 闪烁

**修改**:
- `frontend/src/VideoPlayer.jsx`: loadSource 依赖从 `activeVideo`（对象引用）改为 `activeVideoUrl`（URL 字符串），内部用 `activeVideoRef.current` 访问最新对象。URL 不变则 loadSource 不重建，播放器不销毁
- `frontend/src/views/DetailView.jsx`: handleTags 中 setLocalVideos 增加新旧 URL 对比守卫，URL 相同时不更新 state，避免不必要的重新渲染

## 爬取速度优化 — 极限加速

**目标**: 将爬取速度加到最快，消除所有人为限速点。

**修改文件**:
- `crawler.js`: 1) maxSockets 64→128 + maxFreeSockets 32 2) 重试退避 800ms→500ms 3) 详情页视频地址串行解析改 Promise.all 并行 4) 今日页 2 页串行改 Promise.allSettled 并行 5) 页间 sleep 150ms→50ms 6) 默认并发 6→15 7) loadIndex 加内存缓存避免每批 flush 都重读磁盘 8) saveIndex 改异步 writeFile
- `server.js`: 所有 crawl() 调用 concurrency 3→15, pushEvery 10→5
- `lib/crawl-eta.js`: AVG_REQUEST_SEC 0.45→0.35, 并发预估上限 12→30

**效果预估**: 并发 5 倍提升（3→15），视频解析并行化，今日页并行化，索引 I/O 从同步改异步+缓存，总提速约 4-5 倍
